# Public API review and the backward compatibility promise

## Context
ROADMAP 1.0: the public API freezes. Today 81 of the 93 classes in `src/` carry no `@internal`. After 1.0, Semantic Versioning would therefore cover the inside of the pipeline too, for example:
- `Html\Segmenter`, `Html\RunAnchor`, `Html\LoadedDocument`;
- `Provider\Llm\Bridge\Retrier`, `TransportFailure`;
- `Provider\Llm\PromptBuilder`, `Domain\UnitTextToken`.

Every refactoring of those would then be a major release. ARCHITECTURE §4 describes the stable surface, but nothing marks or checks it.

## Scope
- New ADR: what the BC promise covers. Proposed tiers:
  - **public API**: `HtmlTranslator`, options, results, profiles, exceptions, provider and chat-model ports, adapters and their configs;
  - **extension points**: interfaces and contract test cases for third-party providers and chat models;
  - **internal**: everything else, `@internal`, no promise.

  The ADR also says what may change in a minor version: new optional named parameters, new enum cases (as with `IssueType::TermViolation`) and new methods on interfaces (no).
- Classify every class in `src/`. Mark internals `@internal`, and decide for each injectable collaborator of `HtmlTranslator` (`segmenter`, `reassembler`, …) whether it stays injectable.
- Remove leftovers that 1.0 should not carry: provisional parameters, deprecated paths, and names that ARCHITECTURE §2 does not use.
- A public API snapshot test in `tests/Unit/Architecture` (next to `NoLegacyDomTest`): a committed file lists the public classes and the signatures of their public members, generated by reflection. The test fails on any difference, so every API change is a visible diff in review. A script regenerates the file.
- ARCHITECTURE §4 and the README link the promise.

## Acceptance criteria
- [ ] The ADR is accepted, and every class in `src/` is public, an extension point or `@internal`, as the ADR defines.
- [ ] The snapshot test fails when a public signature changes and passes after regeneration.
- [ ] CHANGELOG lists every removal or rename under "Removed" / "Changed".
- [ ] `composer check` green.

## Open questions (decide before starting)
- **Collaborators.** Keep `loader`, `segmenter`, `validator`, `reassembler` and `batcher` injectable (and therefore public), or make them internal and keep only the configuration objects (`SkipRules`, `TranslatableAttributes`, `TokenEstimatorInterface`)? Recommendation: internal. Injecting a different segmenter is not a supported use case.
- **Enum cases.** Is a new case of a public enum a minor or a major change? Recommendation: minor, documented as such, because exhaustive `match` on library enums is the caller's risk.

## Out of scope
Changing behaviour. This issue only classifies, documents and removes leftovers.
